# `std::mem::transmute` в Rust

## 🧩 Что это

```rust
pub const unsafe fn transmute<Src, Dst>(src: Src) -> Dst
```

`transmute` **переинтерпретирует биты** одного типа как другой тип, **не меняя сами биты**. По сути — это `memcpy` из одной переменной в другую с последующим «забыванием» исходного значения. Компилятор проверяет **только размер** (`size_of::<Src>() == size_of::<Dst>()`), но **не** корректность результата.

```rust
fn main() {
    let v = 10_f32;

    let v2 = unsafe {
        std::mem::transmute::<_, u32>(v)
    };

    println!("v: {v}, v2: {v2}");  // v: 10, v2: 1092616192
}
```

`10.0f32` в IEEE 754 — это `0x41200000` = `1092616192` в десятичном. Функция не «превращает» 10 в 1092616192 — она показывает, **как те же 4 байта выглядят как `u32`**.

---

## ⚠️ Когда `transmute` безопасна

Функция корректна **только если выполнены оба условия**:

1. **Одинаковый layout.** Оба типа имеют одинаковый размер и выравнивание. `f32` и `u32` — оба 4 байта, ✅.
2. **Значение остаётся валидным в новом типе.** Любая битовая комбинация `u32` — валидный `u32`. Но **не любая** — валидный `bool`, `char`, `NonZeroU32`, enum без `repr`.

### ✅ Можно

| Из | В | Почему |
|----|---|--------|
| `f32` | `u32` | Оба 4 байта, любое значение `u32` валидно |
| `u64` | `f64` | Оба 8 байт |
| `*const T` | `usize` | Одинаковый размер на целевой платформе |
| `[u8; 4]` | `u32` | Оба 4 байта |
| `&T` | `*const T` | Ссылка — это указатель |

### ❌ Нельзя

| Из | В | Почему |
|----|---|--------|
| `u8` | `bool` | Только `0` и `1` валидны; `2` → UB |
| `u32` | `char` | Не все `u32` — валидные Unicode scalar values |
| `u32` | `NonZeroU32` | `0` невалиден |
| `&T` | `&mut T` | Нарушает правила алиасинга → UB |
| `struct A` | `struct B` | `repr(Rust)` не гарантирует порядок полей |
| `&T` | `&'static T` | Продление времени жизни → висячие ссылки |
| `u8` | `enum MyEnum` | Не все значения валидны для enum |

## 🧨 Опасности

### 1. Создание недопустимых значений (UB)

```rust
let b: bool = unsafe { std::mem::transmute(2u8) };
// UB: bool может быть только 0 или 1
```

Даже если вы **никогда не используете** этот `bool`, сам факт его существования — уже UB. Компилятор вправе предполагать, что `bool` — это 0 или 1, и оптимизировать соответственно.

### 2. Нарушение алиасинга

```rust
let r: &i32 = &42;
let m: &mut i32 = unsafe { std::mem::transmute(r) };
// UB: разделяемая ссылка превращена в изменяемую
```

Компилятор предполагает, что данные за `&` не меняются. Нарушение — UB, даже если вы ничего не записали.

### 3. Продление времени жизни

```rust
unsafe fn extend<'a>(r: &'a i32) -> &'static i32 {
    std::mem::transmute(r)
}
```

Возвращённая ссылка живёт «вечно», хотя данные могут быть уже освобождены → висячий указатель → UB.

### 4. Padding в структурах

```rust
#[repr(C)]
struct A { a: u8, b: u32 }   // 3 байта padding
```

`transmute::<A, [u8; 8]>()` скопирует и padding, который **неинициализирован** → UB.

### 5. Порядок полей

```rust
struct A { x: u8, y: u32 }
struct B { y: u32, x: u8 }
// transmute::<A, B>() — UB: repr(Rust) не гарантирует порядок
```

## 🛡️ Безопасные альтернативы

В **99% случаев** есть безопасная замена. Используйте её, а не `transmute`.

| Задача | Безопасная замена |
|--------|-------------------|
| `f32` → `u32` (биты) | `f32::to_bits()` |
| `u32` → `f32` (биты) | `f32::from_bits()` |
| `f64` → `u64` (биты) | `f64::to_bits()` |
| Число → байты | `u32::to_ne_bytes()`, `u32::to_le_bytes()`, `u32::to_be_bytes()` |
| Байты → число | `u32::from_ne_bytes()`, `from_le_bytes()`, `from_be_bytes()` |
| `&str` → `&[u8]` | `str::as_bytes()` |
| `&[u8]` → `&str` | `std::str::from_utf8()` |
| Указатель → `usize` | `ptr as usize` |
| `&T` → `*const T` | `&t as *const T` |
| Неинициализированная память | `MaybeUninit<T>` |
| Структура → байты | `bytemuck::bytes_of()` |
| Байты → структура | `bytemuck::from_bytes()` |
| Любая POD-конверсия | `bytemuck` или `zerocopy` |

### 💻 Пример: ваш код через безопасную альтернативу

```rust
fn main() {
    let v = 10_f32;

    // Безопасно, без unsafe:
    let v2 = v.to_bits();

    println!("v: {v}, v2: {v2}");  // v: 10, v2: 1092616192
}
```

`f32::to_bits()` делает **то же самое**, что `transmute::<f32, u32>`, но:
- не требует `unsafe`,
- документирован,
- гарантированно корректен,
- читается лучше.

### 💻 `bytemuck` — для структур

```toml
[dependencies]
bytemuck = { version = "1", features = ["derive"] }
```

```rust
use bytemuck::{Pod, Zeroable};

#[derive(Copy, Clone, Pod, Zeroable)]
#[repr(C)]
struct Header {
    magic: u32,
    version: u16,
    flags: u16,
}

let header = Header { magic: 0xCAFE, version: 1, flags: 0 };
let bytes: &[u8] = bytemuck::bytes_of(&header);
// Безопасно, без unsafe, с проверкой на этапе компиляции
```

`bytemuck` гарантирует на **уровне типов**, что структура — POD (plain old data), без padding, с корректным layout. Если попытаетесь применить к структуре с `String` — ошибка компиляции.

### 💻 `zerocopy` — современная альтернатива

```toml
[dependencies]
zerocopy = "0.8"
```

```rust
use zerocopy::{FromBytes, IntoBytes, Immutable, KnownLayout};

#[derive(FromBytes, IntoBytes, Immutable, KnownLayout)]
#[repr(C)]
struct Header { magic: u32, version: u16, flags: u16 }

let header = Header { magic: 0xCAFE, version: 1, flags: 0 };
let bytes: &[u8] = header.as_bytes();
```

`zerocopy` строже `bytemuck` и ловит больше ошибок на этапе компиляции (например, padding в структуре).

## 🎯 Когда `transmute` всё-таки нужна

Осталось несколько сценариев, где безопасной замены **нет**:

### 1. Указатель → указатель на функцию (FFI)

```rust
fn foo() -> i32 { 42 }

let ptr = foo as *const ();
let f: fn() -> i32 = unsafe {
    std::mem::transmute(ptr)
};
assert_eq!(f(), 42);
```

### 2. Продление времени жизни (очень редко, обычно — признак плохого дизайна)

```rust
unsafe fn extend_lifetime<'b>(r: &'b str) -> &'static str {
    std::mem::transmute(r)
}
```

Применяется, например, при работе с `Box::leak` или глобальными кэшами — но почти всегда есть лучший способ.

### 3. Работа с `repr(C)`-структурами и системными вызовами

```rust
#[repr(C)]
struct Timespec { tv_sec: i64, tv_nsec: i64 }

// где-то в FFI
let ts: Timespec = unsafe { std::mem::transmute(bytes) };
```

Но и здесь `bytemuck`/`zerocopy` безопаснее.

## 🎯 Итог

`std::mem::transmute` — **самая опасная функция** в стандартной библиотеке Rust:

- ✅ **Работает:** переинтерпретирует биты, если размеры совпадают.
- ⚠️ **Опасна:** UB при невалидных значениях, нарушении алиасинга, padding, порядке полей.
- 🛡️ **Заменяема:** в 99% случаев есть безопасная альтернатива — `to_bits`, `from_ne_bytes`, `str::as_bytes`, `bytemuck`, `zerocopy`.

**Правило:** если вы пишете `transmute` — сначала поищите безопасную замену. Если её нет — трижды подумайте, правильно ли вы решаете задачу. В вашем примере `f32 → u32` правильный ответ — **`v.to_bits()`**, а не `transmute`.
